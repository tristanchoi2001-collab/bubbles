# 철 채널 프로그램 개선 조사 — 인계 문서 (2026-10-23)

## 1. 사용자 요청 (원문)
> 너는 앞으로 철 채널 프로그램을 어떻게 개선하고 발전해 나갈지 리서치 진행해줘. 넌 논문 못읽어?

- "철 채널 프로그램" = `steel/`의 영상 처리 프로그램이다(촬영 조건 → 전처리 → U-Net 검출 → 추적 → 측정량 출력 → 품질 점검).
- 목표: 앞으로 무엇을 어떤 순서로 고치고 더할지를, 논문과 우리 측정을 근거로 정한다.
- 사용자는 투명 채널 개발을 멈추고 철 채널에 집중하기로 했다(2026-10-23).
- 논문 방향(열전달·압력 강하 모델, 유사 실험 논문)은 다른 세션이 맡는다. 이 조사는 **프로그램**에 집중한다.
  겹치는 부분("영상에서 무엇을 재야 하는가")은 그쪽 결과(`docs/research/`)를 읽고 맞춘다.

## 3. 지금 프로그램과 데이터 (CLAUDE.md 요약)
- 파일: `steel/1_steel_train.py`(학습), `2_steel_track.py`(검출·추적), `3_tracking_qc.py`(자동 QC), `4_link_audit.py`(사람이 표본 판정).
- 입력: 원본 − 배경. 배경은 프레임마다 affine ECC로 위치를 맞춘다(`BG_REGISTER`). 밝기 맞춤(`BG_MATCH`)은 끔.
  - U-Net 입력 5채널 'bin+sign' = 이진화 B×3 + 어두워진 분 DK + 밝아진 분 DB. 출력 3클래스(배경/내부/경계).
  - 인스턴스는 경계를 벽으로 나누는 hybrid 방식(+ 링 구제, 기포 안 기포 제거).
- 추적: 헝가리안 1:1 + 마스크 겹침으로 합체·분열 판정, 크기별 PIV 초기 속도, 간격 게이트, 흐름 방향 "right"(선단부 = 오른쪽 끝).
- 철 블록 화상(1920×1200 BMP, 백라이트 없음, 배경 밝기 90~180)
  - 기포 내부가 액체보다 어둡다. 직경 100~230 px 기포는 중심까지 −25~−45 계조(잡음 σ≈3).
    큰 슬러그는 테두리에서 50~100 px까지 −20~−30, 중심은 −5~−10, 거대 슬러그 중심은 ≈0.
  - 테두리: 폭 20~25 px의 밝은 띠(+30~+85)와 그 안쪽 어두운 띠. 빛이 위쪽에서 비스듬히 와서 링 밝기가 방향에 따라 다르다.
  - 거품: 직경 5~8 px 미세 기포 무리. 간격 약 10 px인데 프레임당 약 50 px 움직여 하나씩은 추적할 수 없다.
  - 흐름: 오른쪽으로 48~53 px/프레임, dy ≈ 0.
  - 배경과 프레임이 최대 dx 1.7, dy 2.8 px 어긋나고 세로 배율이 0.9964~0.9968이다(카메라나 덮개 변형 추정). 맞추면 잔차가 줄었다.
  - 기포 내부가 어두운 이유는 모른다. 큰 슬러그 안에서 유지되는지도 모른다.
- 아직 안 한 것: 철 채널 라벨링 → 사용자 PC 학습 → 검출 확인. 학습한 철 채널 모델은 아직 없다.
- 투명 채널의 교훈
  - TAU(이전 프레임 마스크 입력), 트랜스포머 맥락 모듈, 부호 채널(DK/DB)은 투명 채널에서 효과가 없었다. 데이터에 그 단서가 없었기 때문이다.
  - **새 입력·학습을 제안하기 전에 그 정보가 데이터에 있는지 원본으로 먼저 잰다.** 재학습 전에는 기존 모델이 실제로 실패하는지부터 본다.
  - 철 채널은 내부 대비(−25~−45)가 있어 5채널이 쓸모 있을 수 있다. 확정은 같은 라벨로 'bin'(3채널)과 비교한 뒤다.

## 4. 조사 질문
각 질문마다 ① 문헌에서 배운 것 ② 우리 프로그램에 이미 있는 것/없는 것 ③ 제안(무엇을, 비용, 위험, 학습 없이 먼저 확인하는 방법, 바꿀 파일·함수)을 쓴다.
투명 덮개 너머로 불투명한 금속 바닥을 위에서 찍는 조건(반사광)에 맞는 문헌을 우선한다. 백라이트 그림자 영상 문헌은 다른 점을 적는다.

- **A. 촬영·조명(프로그램이 촬영에 요구할 조건)**
  - 금속 바닥 위 반사광 영상에서 기포 대비를 높이고 정반사·조명 불균일을 줄이는 방법: 확산광, 교차 편광, 동축·링 조명 등.
  - 노출·fps·모션 블러 기준(기포 크기 대비 프레임당 이동). 지금 50 px/프레임이 추적에 충분한가.
  - 배경 취득: 빈 프레임 여러 장의 중앙값, 가열 중 열팽창으로 생기는 어긋남, 배경 없이 영상에서 배경을 추정하는 방법.
  - 화소당 mm 보정, 간극 1/3/7 mm의 피사계 심도, 덮개 반사, 카메라와 DAQ(열전대·압력계) 동기화.
  - 형광 염료(LIF) 등으로 기체·액체를 직접 구분하는 방법이 금속 바닥에서 되는가. (투명 채널에서 사용자가 염색이 어렵다고 했다. 철 채널에서 되는지는 질문으로 남긴다.)
- **B. 검출**
  - 반사광·불투명 바닥(비등 가열면 위 등) 기포 검출 사례와 방법.
  - 붙은 기포·겹친 기포 분리: 거리맵·흐름 표현(StarDist, Cellpose/Omnipose 류), 경계 클래스 방식과의 비교.
  - 화면보다 큰 슬러그, 거품 무리(개별 대신 영역 분류 + 면적·개수 밀도 추정), 간극에 따른 외형 차이(7 mm는 기포가 겹쳐 보일 수 있음).
  - 라벨 효율: SAM 계열 보조 라벨, 능동 학습, 합성 데이터.
    - 우리 측정에서 내부 어두워짐이 배경 밝기와 무관한 덧셈형이었다 → 차분 영역의 copy-paste 합성이 물리적으로 맞는지 문헌으로 판단한다.
  - 전후 프레임(시간) 정보, 불확도 추정(TTA, MC dropout), 간극·조명이 바뀔 때의 일반화.
- **C. 추적**
  - 합체·분열을 다루는 연결 방법: LAP(u-track, TrackMate), 네트워크 흐름·전역 최적화, 트랙렛 잇기, 크기별 운동 모델.
  - 거품 무리: 개별 추적 대신 PIV·광류로 속도장을 내는 방법.
  - 비등이면 화면 안 핵생성·성장이 진짜 사건이다 → 지금 QC의 "내부 신규"를 어떻게 해석·분리할지.
  - 평가: 추적 정답 만들기(반자동), HOTA 등 지표, 합체를 표현하는 평가. 지금 `4_link_audit.py`(표본 판정)와 비교.
- **D. 측정량과 검증**
  - 영상 → 투영 기공률 → 실제 기공률(간극별 가정, 액막 보정), 기포 속도·빈도·길이 분포, 계면 길이 밀도, 가열면 덮임률 등.
    논문 세션의 가설(`docs/research/agent_brief.md` §2)이 쓰는 지표를 프로그램이 어떤 형식으로 내야 하는지.
  - 압력·온도 신호와 영상의 교차 검증(통과 빈도와 압력 변동 스펙트럼, 상호상관 등). 정답 없이 추적 품질을 확인하는 방법이 된다.
  - 불확도 전파: 화소 보정, 검출 문턱, 추적 오연결률(연결 감사 결과) → 속도·기공률.
- **E. 소프트웨어**
  - 긴 영상 처리 속도(GPU, 타일, 반정밀도), 실행 기록·재현성(설정 파일, 실험 조건 메타데이터), 조건별 자동 요약 보고서.
  - 쓸 만한 공개 도구(OpenPIV, PIVlab, TrackMate, trackpy, OpenLPT 등)를 우리 코드와 비교한다(바꿀지, 일부만 참고할지).
