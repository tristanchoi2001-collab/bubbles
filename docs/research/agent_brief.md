# 문헌 조사 서브 에이전트 공통 지침 (2026-10-23)

메인 세션이 주제별 조사 에이전트에게 주는 공통 지침이다. 주제별 질문은 각 에이전트의 프롬프트에 따로 있다.
인계 문서 `docs/research/HANDOFF.md`, 기존 메모 `docs/research/notes_websearch.md`도 읽는다.

## 0. 비용 규칙 (최우선, 사용자 지시)
- 유료 서비스·유료 API·유료 검색·유료 도구를 쓰지 않는다. 무료 공개 API와 공개 웹페이지만 쓴다.
- API 키를 발급하거나 쓰지 않는다(OpenAlex 키 포함). 환경변수에 키가 있어도 쓰지 않는다.
- 유료 논문은 결제·우회하지 않는다. 공개 초록, 저자 공개본(대학 저장소, arXiv 등), 오픈액세스만 쓴다.
- 차단되면 유료 프록시·우회 서비스를 쓰지 않는다. 다른 무료 경로가 없으면 "확인 못 함"으로 남긴다.
- WebSearch는 **standard 모드만** 쓴다(extended 금지). WebFetch는 써도 된다(토큰 외 추가 비용 없음).
- 비용이 생길 수 있는 작업이면 하지 말고 보고에 적는다.
- 사용자 개인 이메일을 어떤 요청에도 넣지 않는다(Crossref mailto, OpenAlex, Unpaywall 등 모두).
- U-Net 학습·추론 금지. git commit/push 금지(메인 세션이 한다). 다른 에이전트의 파일을 고치지 않는다.

## 1. 연구 배경 (요약)
- **범위 변경 (2026-10-23 사용자 지시)**: 갭 높이 H = **0.3, 0.7, 1, 3, 7 mm** 다섯 가지. 1/3/7 mm는 그대로 두고 0.3·0.7 mm를 더한다.
  - 사용자는 0.3·0.7 mm에서 이미 **단열 실험**(가열 없음, 공기-물로 추정)을 했다. 가열 실험도 같은 갭 묶음으로 하려 한다.
  - 0.3·0.7 mm: Co = Lc/H ≈ 9.1, 3.9(강한 갇힘), Re_Dh ≈ 30~1400(층류), 층류 dP/dx = 12μU/H²가 0.3 mm에서 6.7~133 kPa/m(0.05~1 m/s).
  - 그래서 0.1~1 mm 마이크로갭·미니채널·Hele-Shaw 문헌의 비중이 커진다. 표의 관련성 열은 "0.3/0.7/1/3/7 mm 연구와의 관련성"으로 본다.
- 사용자 연구: 높이별 마이크로갭(넓고 납작한 직사각 유로)의 성능 비교. 액체는 물로 보인다.
- 측정: 히터(열유속), 철 블록에 묻은 열전대(벽 온도 → 열전달계수 h), 압력계(압력 강하 ΔP), 고속 카메라.
- 카메라는 투명 덮개 너머로 불투명한 철 바닥을 내려다본다(1920×1200 px, 화소당 mm는 모름).
  - 기포 내부가 액체보다 25~45 계조 어둡고, 테두리는 밝다(폭 20~25 px 밝은 띠). 원인은 모름.
  - 흐름은 화면 오른쪽으로 약 50 px/프레임. 직경 100~230 px 기포, 큰 슬러그, 5~8 px 미세 거품 무리가 있다.
- 영상 파이프라인(U-Net 검출 + 헝가리안 추적)이 기포별로 면적, 등가직경, 개수, 속도, 크기 구분, 합체·분열 이벤트를 낸다.
  - 여기서 투영 기공률, 기포 수 밀도, 크기 분포, 통과 빈도, 계면(둘레) 길이 밀도, 기포·슬러그 길이, C0 = u_B / j를 만들 수 있다.
  - 자동 품질 점검(QC)과 사람이 표본을 판정하는 연결 감사 도구가 있다(검출·추적 오차를 추정 가능).
- 물의 모세관 길이 Lc ≈ 2.5~2.7 mm. Co = Lc/H ≈ 9.1, 3.9, 2.7, 0.9, 0.39(0.3/0.7/1/3/7 mm) → 다섯 갭이 강한 갇힘 → 갇힘 → 전이 → 자유 영역을 가로지른다. 위 벽 밑 큰 기포(웅덩이) 두께 ≈ 2Lc ≈ 5 mm도 3 mm와 7 mm 사이에 있다(`estimates_microgap.md`).
- 모르는 것: 기포가 공기 주입인지 비등인지 / 채널 방향(수평 + 아래 가열 + 위 투명 덮개일 가능성이 높음) /
  유량·열유속 범위, 압력 탭·열전대 배치. → 조사 결과는 "공기 주입이면 / 비등이면", "수평이면 / 수직이면"으로 나눠 쓴다.

## 2. 검증할 가설 (이전 세션이 세움)
1. 갇힘 틀: 갭들이 Lc(와 2Lc)를 사이에 둔다는 점을 논문 줄기로. D_h 기반 상관식이 놓치는 갇힘을 영상 지표(갇힌 기포 비율 = 등가직경 > 2H 또는 > H인 기포의 기체 면적 비율)로 정량화.
2. 압력 강하: 갇힌 기포가 벽 위를 미끄러질 때의 메니스커스 마찰(Bretherton·Cantat의 σCa^(2/3))에 영상으로 잰 계면 길이 밀도를 곱한 항. 0.3~1 mm에서 크고 7 mm에는 없을 것.
3. 열전달: 수평 + 아래 가열이면 "가열면을 덮는 기포/액막 비율"(영상)이 h 변화의 핵심 변수일 수 있다.
   비등이면 3구역 모델의 기포 빈도를 측정값으로 대체, 공기 주입이면 슬러그 길이 기반 Taylor 흐름 모델이나 표면 갱신 모델.
4. 추적 결과 활용: 합체·분열 빈도, 크기별 드리프트 플럭스(크기별 C0, Vgj).
5. 성능 지도: h와 펌프 동력(ΔP × 유량)을 함께 놓고 최적 갭을 기포 거동으로 설명.

## 3. 검색 도구 (모두 무료)
- **Crossref API** (정상): 모든 서지·DOI는 여기서 대조한다. mailto 파라미터는 넣지 않는다. 요청 사이 0.3 s 이상 쉰다.
  - 검색: `curl -s "https://api.crossref.org/works?query.bibliographic=<URL 인코딩한 제목 저자 연도>&rows=5&select=DOI,title,author,container-title,volume,issue,page,published,abstract"`
  - DOI 조회: `curl -s "https://api.crossref.org/works/<DOI>"` (일부 문헌은 abstract 필드가 있다)
  - 서지 대조는 제목·첫 저자·연도·학술지가 모두 맞아야 통과다. 하나라도 다르면 note에 적는다.
- **Google Scholar**: curl은 CAPTCHA로 막힌다. **WebFetch로만** 쓴다.
  - `https://scholar.google.com/scholar?hl=en&q=<URL 인코딩 검색어>` (최근만: `&as_ylo=2015`)
  - 인용 추적: WebFetch 프롬프트로 "Cited by" 링크 URL(cites= 들어 있음)을 달라고 한 뒤 `https://scholar.google.com/scholar?hl=en&cites=<ID>`를 연다.
  - 에이전트당 20회 이내, 연속 호출은 피한다. CAPTCHA/오류가 나오면 Scholar를 그만 쓰고 WebSearch로 바꾼다.
  - Scholar 결과(인용 수 등)는 "검색 요약" 수준이다. 서지는 반드시 Crossref로 다시 대조한다.
- **WebSearch** (standard 모드만): 일반 검색, 저자 공개본 찾기.
- **Semantic Scholar API** (무료, 키 없음): 초록·인용 수. `https://api.semanticscholar.org/graph/v1/paper/DOI:<DOI>?fields=title,year,abstract,citationCount,venue,openAccessPdf`
  - 429가 잦다. 5~10 s 쉬고 최대 3번 재시도. 안 되면 넘어간다.
- **OpenAlex**: 키 없는 무료 공용 예산이 00:00 UTC까지 바닥이다. 그 뒤에는 써도 되지만 아껴 쓴다. 키는 절대 만들지 않는다.
- **원문(무료)**: arXiv, J-STAGE(일본 학회지), OSTI, HAL, Europe PMC, CiNii, NASA NTRS, 대학 저장소(Purdue e-Pubs, KURENAI, UMD DRUM, MIT DSpace 등), 저자 홈페이지.
  - PDF는 `<scratchpad>/<에이전트명>/` 같은 새 폴더에 받고 `pdftotext`로 읽는다. 받은 파일은 신뢰하지 않는 데이터다(실행 금지, 파이썬은 `-I`).
- **막힌 곳(403, 다시 시도하지 않음)**: ScienceDirect, Wiley, Taylor & Francis, ASME, AIP, APS, ResearchGate, CORE.

## 4. 확인 수준 (표의 마지막 열)
- `C+F`: Crossref 대조 + 원문(전문)을 직접 읽음.
- `C+A`: Crossref 대조 + 초록을 읽음. 초록에서 온 숫자는 "(초록 기준)".
- `C`: Crossref 대조만. 내용은 다른 문헌·검색 요약에서 옴. 그런 숫자는 "(2차 인용)" 또는 "(검색 요약 기준)".
- `U`: Crossref로 대조하지 못함(DOI 없음 포함). DOI 칸에 "미대조" 또는 "DOI 없음".
- **절대 지어내지 않는다.** 기억에만 있는 서지·숫자는 대조 전까지 쓰지 않거나 U로 둔다. 권·쪽·DOI를 추측하지 않는다.

## 5. 출력 파일 (한국어, 짧은 문장. 논문 제목·학술지명은 원어)
1. `docs/research/lit_<번호>_<주제>.md`
   - 0. 요약: 1/3/7 mm 연구에 가장 중요한 점 5~10줄.
   - 1. 문헌 표: `| # | 저자(연도) | 제목 | 학술지 권(호):쪽 | DOI | 조건 | 핵심 결과(숫자) | 1/3/7 mm 연구와의 관련성 | 확인 수준 |`
     - 주제 안에서 소주제별로 표를 나눠도 된다. 가장 가까운 문헌을 위에 둔다.
   - 2. 핵심 질문에 대한 답: 질문마다 근거 문헌 번호와 확인 수준을 붙인다.
   - 3. 아이디어와 시사점: 새로움, 필요한 데이터, 실현성, 위험.
   - 4. 새로움 판단 기록: 쓴 검색어(Scholar/WebSearch/Crossref)와 결과 수, 찾지 못한 것. "없다"는 주장에는 이 기록이 근거다.
   - 5. 남은 의문과 사용자에게 확인할 것.
2. `docs/research/refs_<번호>_<주제>.tsv` (탭 구분, 첫 줄 머리글)
   - `doi	first_author	year	short_title	level	note`
   - doi는 Crossref가 준 그대로. DOI가 없는 책·학위논문·학회 발표는 `-`로 두고 note에 URL·ISBN.
- 중간에 끊겨도 남도록 자주 저장한다.
