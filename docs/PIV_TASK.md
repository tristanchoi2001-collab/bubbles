# 작업: 추적에 PIV 상호상관 기반 초기 속도 추정 도입

이 파일은 claude.ai 채팅에서 진행한 진단과 설계를 Claude Code로 넘기기 위한 작업 지시서다.
참고 파일: `piv_prior.py`(속도장 참고 구현), `tracker.py`(채팅에서 개선한 트래커 v2), `3_tracking_qc.py`(추적 QC).
이 저장소의 코드가 위 파일들과 다를 수 있으니, **먼저 저장소의 실제 코드를 읽고 대응 관계를 파악할 것.**

---

## 1. 프로젝트 개요

마이크로갭(약 1 mm) 내 기액 이상류의 기포를 고속 촬영 영상에서 검출·추적한다.

```
배경차분 이진화 → U-Net(배경/기포내부/기포경계 3클래스) → 경계를 벽으로 영역 분할 → 기포 인스턴스 마스크
→ LeadingEdgeLapTracker (헝가리안법 1:1 대응 + 마스크 겹침/Union IoU 기반 합체·분열 판정)
→ result_tracking.csv / result_area_count.csv / 오버레이 / qc_report.json
→ 3_tracking_qc.py (추적 정확도 자동 점검)
```

연구 목적상 중요한 출력: 기포별 속도(슬립비, 드리프트 플럭스 C0 = u_B / j), 기포 길이. 면적 가중이므로 큰 기포가 지배적.

## 2. 진단 결과 (실제 데이터 QC)

느린 유속 조건:
- large: 예측 위치 오차 중앙값 4.6 px, 기준 초과 4.8% → 안정
- tiny / small: 기준 초과 74% / 42% → 불안정
- 촬영 조건 지표 (다음 프레임 최근접 거리 ÷ 같은 프레임 최근접 거리) 0.47~0.62
  → 기포가 프레임당 이웃 간격의 약 절반을 이동. 최근접 선택만으로는 애매하지만 속도를 알면 추적 가능한 범위
- 부트스트랩 게이트 85 px > 이웃 간격 31 px

원인:
1. 작은 기포는 검출에서 자주 깜빡이고, 다시 나타날 때마다 **속도 0으로 새 트랙 시작** → 그 자리에 들어온 이웃을 잡음
2. 게이트가 이웃 간격보다 훨씬 넓음 (부트스트랩은 "이동량"으로 게이트를 정하지만 게이트는 "예측 오차"에 적용됨 — 설계 결함)
3. 작은 기포는 모양이 다 비슷해 형상 IoU가 구분에 도움 안 됨

## 3. 이미 적용한 개선 (트래커 v2, `tracker.py`)

- `USE_FLOW_PRIOR`: 새 트랙 초기 vy = 반경 150 px 내 추적 중 트랙(hits ≥ 3)의 vy 중앙값
- `SPACING_GATE_FRAC = 0.7`: 예측 위치–검출 거리 ≤ 0.7 × (그 검출의 같은 프레임 최근접 이웃 거리)일 때만 대응. 화면 끝에 닿은 검출은 제외
- `COAST_GATE_GROWTH = 0.5`, `SHAPE_AREA_REF = 300`(작은 기포는 형상 IoU 가중치를 면적 비례로 축소)
- CSV 속도 열 EMA 초기값 편향 수정 (첫 값을 0이 아닌 첫 실측 이동량으로)

정답 ID가 있는 합성 데이터에서 잘못 연결 비율:
- 중속: tiny 15.4% → 1.3%, small 4.2% → 0.8%, 끊김은 동일 수준
- 고속: tiny 20.3% → 2.9%, small 10.5% → 1.6%

## 4. 남은 문제

고속 조건 실제 데이터에서 **프레임당 약 73개 트랙이 화면 내부에서 새로 시작**(과도한 끊김), 큰 기포의 끊김도 증가.
추정 원인:
- (a) 간격 게이트의 최근접 이웃을 **크기와 무관하게** 계산 → 슬러그 옆의 작은 기포 때문에 슬러그의 게이트가 좁아짐
- (b) 주변 중앙값 prior가 **크기별 속도 차이**를 무시 (고속에서는 슬러그가 작은 기포보다 훨씬 빠름)

새 기포의 초기 속도 추정 오차 (고속 합성, 실제 이동 tiny 25 / small 30 / large 42 px/frame, 중앙값 px/frame):

| 방법 | tiny | small | large |
|---|---|---|---|
| 속도 0 | 24.1 | 30.2 | 42.5 |
| 주변 트랙 중앙값 (v2, 이상적 경우) | 4.0 | 3.3 | 15.2 |
| 상호상관, 전체 영상 | 10.6 | 3.2 | 0.3 |
| **상호상관, 크기별 분리** | **1.6** | **1.0** | **0.3** |

전체 영상 상관은 창의 피크가 픽셀이 많은 큰 기포를 따라가므로, 크기별로 분리해야 함.

## 5. 할 일

### 5-1. PIV 속도장 모듈
`piv_prior.py`의 알고리즘을 이식하되:
- 입력은 이진화 영상이 아니라 **U-Net 인스턴스 마스크**로 만든 크기별 영상 (정지된 배경 잔여물 영향 제거).
  크기 구분은 QC와 동일하게 면적 tiny < 50, small 50–500, large ≥ 500 px.
- 2단계 FFT 상호상관: 1단계 창 256 / 간격 128 → 2단계 창 128 / 간격 64, 1단계 결과만큼 t+1 쪽 창을 이동(window offset)
- 가우스 3점 서브픽셀, 피크 비율(1위/2위) ≥ 1.2, 정규화 중앙값 검증(종·횡 중 하나라도 이탈 시 둘 다 무효), 무효는 주변 중앙값으로 채움
- **크기 클래스별 창 크기 설정 가능**하게 (tiny는 기포가 드물어 유효 창이 32% 정도뿐 → 더 큰 창)
- 프레임 쌍 (t, t+1)마다 계산. 검출이 전 프레임 끝난 뒤 추적하므로 t+1 사용 가능

### 5-2. 트래커 통합
- 새 트랙의 초기 vy = **같은 크기 클래스** 속도장의 해당 위치 값. 설정 `USE_PIV_PRIOR`(기본 True).
  속도장 무효 시 대체 순서: 크기 유사 이웃 중앙값 → 0
- 현재 트래커는 x 방향 예측이 없음(dx는 직전 cx와 비교). 속도장의 dx를 새 트랙 x 예측에 쓸지 검토하고 근거와 함께 보고
- 간격 게이트의 최근접 이웃 거리를 **면적비 ≤ AREA_RATIO_GATE인 이웃만**으로 계산 (실제로 혼동 가능한 이웃만)
- 기존 주변 중앙값 prior도 크기 유사 이웃으로 한정
- **변경 금지**: 합체·분열 판정 로직, CSV 열 구성, 오버레이 형식

### 5-3. QC 수정 (`3_tracking_qc.py`)
- 실제 고속 데이터에서 large의 SWAP_LIKELY 상대 후보가 중앙값 9개, 최대 126개 → 과대계상
- 상대 후보는 **면적비 ≤ 3인 기포만**, 반경 = min(2 × 등가직경, 200 px)
- 상세 문자열은 ID 중복 제거, 최대 5개 + 「他N件」

## 6. 검증 (필수, 결과를 표로 보고)

1. **정답 ID가 있는 합성 데이터**를 생성하는 스크립트 작성
   - 영상 1174×464, 위로 흐름, 슬러그 + 작은 기포 + 아주 작은 기포
   - 중속(크기별 속도 거의 같음)과 고속(슬러그가 빠름, 프레임마다 ±3 px/frame 출렁임) 두 조건
   - tiny 25%, small 10% 확률로 검출 누락
   - U-Net 대신 정답 마스크로 만든 확률맵을 넣는 가짜 검출기
   - 지표: 크기별 **잘못 연결 비율**, 정답 기포당 **트랙 수**(끊김)
2. 비교: 기존 트래커 / v2 / PIV prior
3. 회귀 테스트 (모두 같은 프레임에 같은 판정이어야 함)
   - 뒤 슬러그가 앞 슬러그 꼬리에 붙는 합체, 앞뒤 분열, 슬러그 옆에 새로 나타난 기포 = new
   - 3중 합체, 부모가 1:1 대응 안 되는 3중 분열(최대 조각이 ID 계승), 화면 끝 이탈·빈 프레임
4. 실제 데이터: 느린·고속 조건에서 QC 전후 비교 (tiny/small 기준 초과, INTERIOR_NEW/LOST, 면적 가중 의심 비율)
5. 프레임당 계산 시간

## 7. 주의

- **비등(가열) 실험**에서는 핵생성 기포가 정지 상태에서 출발하므로 PIV prior가 오히려 틀린다.
  옵션으로 끌 수 있게 하고, "같은 위치에서 반복 발생하는 기포는 prior 0" 처리를 TODO로 남길 것.
- 속도장은 **예측용**이다. 측정 결과(기포 속도)는 개별 추적에서만 낸다.
- 틀린 연결보다 끊김이 낫다(끊김은 샘플 손실, 틀린 연결은 잘못된 속도 혼입). 이 원칙을 유지할 것.
